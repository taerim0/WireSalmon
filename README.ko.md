# 🐟 WireSalmon

[English](README.md) | **한국어**

**바로 써 보기: <https://taerim0.github.io/WireSalmon/>** (샘플과 파일 열기만 가능, 실시간 캡처는 로컬 실행 필요)

사람을 위한 Wireshark — 패킷을 대화 단위로 묶어 쉬운 말로 설명해 주는 학습용 패킷 분석기입니다.

Wireshark는 패킷을 한 줄씩 보여 줍니다. 처음 배우는 사람이 궁금한 건 "방금 무슨 일이 일어났나"입니다. WireSalmon은 같은 캡처를 읽어서 그 질문에 먼저 답합니다.

## 기능

- **패킷 줄 대신 대화** — 패킷을 "이름 찾기: example.com", "암호화된 웹 통신: example.com" 같은 대화로 묶어 보여 줍니다.
- **시퀀스 다이어그램** — 대화마다 두 상대 사이의 화살표로 그립니다. TCP는 연결 맺기, 데이터 주고받기, 연결 끊기로 구간을 나눕니다.
- **쉬운 말 설명** — `[SYN, ACK] Seq=0 Ack=1` 대신 *"② 연결 수락 — '좋아요, 저도 준비됐어요'"* 라고 보여 줍니다.
- **진단** — 대화마다 무엇이 잘못됐는지와 흔한 원인을 알려 줍니다. 연결 거부, 응답 없음, 강제 종료, 재전송, 없는 이름, 답하지 않는 DNS 서버, HTTP 오류, 답 없는 핑을 찾아냅니다. 문제가 있는 대화는 목록에 표시되고 따로 모아 볼 수 있습니다.
- **어디서 시간이 걸렸나** — 대화를 이름 찾기, 연결 맺기, 암호화 인사, 서버 응답 대기, 응답 받기로 나눠 보여 주고 느린 구간을 짚어 줍니다.
- **HTTP 메시지로 읽기** — 암호화되지 않은 HTTP는 여러 패킷에 나뉘어 온 조각을 이어 붙여 요청과 응답 전체로 보여 주고, 헤더와 본문을 실어 온 패킷으로 바로 갈 수 있습니다. 순서가 바뀌거나 다시 온 조각, Content-Length와 조각(chunked) 전송을 처리하며, 본문이 불완전하면 그렇다고 알립니다. 압축된 본문은 풀지 않습니다.
- **봉투 구조** — 이더넷 → IP → TCP → HTTP를 겹친 봉투로 보여 주고 필드마다 설명을 붙입니다. 봉투에 마우스를 올리면 실제 바이트에서 해당 부분이 표시됩니다.
- **한국어와 영어** — 상단에서 언제든 언어를 바꿀 수 있고, 캡처를 열어 둔 상태에서도 바로 바뀝니다. 선택은 기억되며, 처음 열 때는 브라우저 언어를 따릅니다.
- **세 가지 시작 방법** — 내장 샘플(잘 되는 경우 하나, 잘 안 되는 경우 하나), `.pcap` / `.pcapng` 파일(끌어다 놓기), 실시간 캡처.

파일은 브라우저 안에서만 해석합니다. 어디에도 업로드하지 않습니다. [개인정보](#개인정보) 항목을 참고하세요.

## 지원 프로토콜

자세히 해석: Ethernet(VLAN), ARP, IPv4, IPv6, ICMP, ICMPv6, TCP, UDP, DNS, mDNS, LLMNR, DHCP, HTTP/1.x, TLS(핸드셰이크 메시지와 접속 사이트 이름).

그 밖의 트래픽은 잘 알려진 포트 번호로 이름만 붙입니다(SSH, NTP, SSDP, QUIC 등).

## 시작하기

Node.js 24가 필요합니다.

```bash
npm install
npm run dev
```

`http://localhost:5173`을 열고 샘플을 고르세요.

### 실시간 캡처

브라우저는 네트워크 카드를 직접 읽을 수 없습니다. 그래서 실시간 캡처는 `dumpcap`을 실행해 WebSocket으로 패킷을 흘려보내는 작은 로컬 헬퍼를 거칩니다.

- [Wireshark](https://www.wireshark.org/)를 설치하세요(Windows는 Npcap 포함). `dumpcap`이 함께 설치됩니다.
- 캡처하려는 컴퓨터에서 `npm run dev`로 실행하세요. 정적으로 호스팅한 사본에서는 실시간 캡처를 쓸 수 없습니다.
- `dumpcap`이 기본 위치에 없으면 `WIRESALMON_DUMPCAP` 환경 변수에 전체 경로를 넣으세요.

캡처 소켓은 `localhost`의 같은 페이지에서 온 연결만 받습니다. 패킷이 50,000개에 이르면 캡처가 자동으로 멈춥니다.

Windows 11에서 확인했습니다. Linux와 macOS의 일반적인 `dumpcap` 위치도 찾도록 되어 있지만 아직 테스트하지 못했습니다.

## 개인정보

캡처에는 비밀번호, 쿠키, 내부 주소가 들어 있을 수 있습니다. 그래서 WireSalmon은 캡처가 내 컴퓨터 밖으로 나가지 않게 만들었습니다.

- **서버가 없습니다.** 사이트는 정적 파일뿐입니다. 캡처 파일은 브라우저의 자바스크립트가 해석하고, 실시간 캡처는 내 컴퓨터와 내 브라우저 사이에서만 오갑니다.
- **직접 확인할 수 있습니다.** 개발자 도구의 네트워크 탭을 연 상태에서 캡처 파일을 열어 보세요. 요청이 하나도 생기지 않습니다.
- **브라우저가 강제합니다.** 빌드한 사이트에는 다른 서버로의 연결을 금지하는 보안 정책(Content Security Policy)이 들어 있습니다. 코드가 바뀌더라도 데이터를 밖으로 보내는 요청(fetch, WebSocket, 이미지, 폼 전송)은 브라우저가 거부합니다.

알아 둘 한계:

- 이 정책은 빌드한 사이트(`npm run build`, `npm run preview`)에만 들어갑니다. 개발 서버(`npm run dev`)는 도구가 인라인 스크립트를 쓰기 때문에 정책이 없습니다.
- 페이지 안의 정책으로는 누군가 코드를 고쳐서 따로 호스팅하는 것까지 막을 수 없습니다. 중요한 캡처는 직접 내려받은 코드로 실행하세요.

## 명령어

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 실행 (실시간 캡처 헬퍼 포함) |
| `npm run build` | 타입 검사 후 정적 사이트를 `dist/`에 빌드 |
| `npm run preview` | 빌드한 사이트 실행 (실시간 캡처 헬퍼 포함) |
| `npm test` | 코어 테스트 실행 |

## 폴더 구조

```
src/core/     캡처 해석기(pcap, pcapng), 프로토콜 해석, 대화 묶기, 진단, 시간 분해, HTTP 메시지 잇기, 샘플 생성
src/i18n/     화면에 나오는 모든 문장 (언어마다 파일 하나)
src/ui/       React 화면
server/       실시간 캡처 헬퍼 (dumpcap → WebSocket)
test/         코어 테스트
```
